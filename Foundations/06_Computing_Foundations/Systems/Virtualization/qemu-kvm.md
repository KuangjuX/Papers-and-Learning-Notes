# QEMU/KVM

## KVM

KVM（Kernel-based Virtual Machine）是 Linux 内核的虚拟化子系统。用户态程序打开 `/dev/kvm`，通过 `KVM_CREATE_VM` 创建虚拟机，再通过虚拟机文件描述符创建 vCPU、设置内存等资源。`KVM_SET_USER_MEMORY_REGION` 注册 guest physical address 到用户态内存区域的 memory slot；它不意味着一次性建立了全部第二阶段页表。调用 vCPU 的 `KVM_RUN` 才会进入 guest 执行，具体进入指令依赖体系结构，不能统一写成 ARM 的 `eret`。[KVM API §1、§4.10、§4.35](https://docs.kernel.org/virt/kvm/api.html)

## KVM 与 QEMU

可以将 KVM 理解为硬件虚拟化机制的驱动程序。而如何使用这个驱动程序，则需要由用户态的应用程序来决定。也就是说，KVM 决定使用硬件虚拟化的“机制”，而用户态程序提供硬件虚拟化的使用“策略”。

运行在用户态的 QEMU 是一个进程，对应于一个虚拟机。使用 KVM 加速时，每个 vCPU 通常由一个宿主线程运行；QEMU 也有主循环和 I/O 等其他线程，不能反过来说每个线程都是 vCPU。具体而言，一个 QEMU 用户态线程会管理一个对应的 vCPU 的所有寄存器状态，当该线程调用 `KVM_RUN` 接口时，KVM 会将对应的 vCPU 的运行所需的 guest 状态切换到硬件中，并开始执行。对于 Linux 内核而言，调度用户态线程相当于调度其对应的 vCPU。这种方式非常巧妙地复用了 Linux 的调度机制，因此不需要为虚拟化重新实现一套新的调度算法。

作为一个用户态程序，QEMU 拥有自己的虚拟地址空间；但作为用户态虚拟机监控器，它还需要为虚拟机分配客户物理内存。为了支撑虚拟机的运行，QEMU 会使用 `mmap` 系统调用建立用户态虚拟地址区域，并将相应区域注册为客户物理内存；宿主虚拟地址连续不代表宿主物理页连续。此外，因为虚拟机内存本质上属于 QEMU 进程内部的内存，因此 QEMU 可以直接读写虚拟机的内存数据。这不仅可以加速 I/O 虚拟化的数据传输（例如 QEMU 可以直接读取虚拟机指定的 DMA 内存区域），还可以方便 QEMU 实现虚拟机热迁移等功能。
